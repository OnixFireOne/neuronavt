## Коротко
Автор собрал пять типичных сбоев при работе Claude Code в нативной Windows-среде и записал для агента конкретные правила в CLAUDE.md. Главный вывод: часто проблема не в модели или коде, а в различиях PowerShell, окружения процессов, localhost и дисковой производительности.

## Контекст
Автор — разработчик, использующий Claude Code в Windows без WSL, в частности для браузерной автоматизации с живыми профилями Chrome. Он фиксировал повторяющиеся ошибки стыка агента с PowerShell 5.1, PATH и Windows-процессами, чтобы агент не повторял неудачные действия.

## Главное
- Автор запускает Claude Code непосредственно в Windows, без WSL; в его окружении доступны Git Bash и PowerShell.
- PowerShell — версии 5.1: в нём нет `&&`, `||`, `?:` и `??`; автор использует `A; if ($?) { B }`.
- Перенаправление `2>&1` у внешних программ может создавать ложный признак ошибки в PowerShell 5.1; проверять следует `$LASTEXITCODE`.
- `Set-Content` по умолчанию может записывать системную ANSI-кодировку, а `Out-File` — UTF-8 с BOM; автор предпочитает инструмент Write либо явный `-Encoding utf8`.
- Git Bash иногда оставляет `*.stackdump`; автор советует добавить этот шаблон в глобальный gitignore.
- Python из Microsoft Store в списке процессов может называться `python3.10.exe`; процессы автор ищет по `CommandLine` через `Get-CimInstance Win32_Process` и проверяет после остановки.
- PATH агента не совпадает с PATH терминала пользователя. Автор задаёт полный путь к Go: `C:\Program Files\Go\bin\go.exe`; `go test ./...` проходит в авторежиме, а `go vet` блокируется классификатором.
- В Next.js 16 dev-режим может блокировать HMR-вебсокет при обращении через `127.0.0.1`; автор открывает dev-сайт через `localhost`.
- Профиль Chrome занимает около 96 МБ. На HDD автор наблюдал disk time 168% и около 200 мс на операцию; Chrome не успевал открыть отладочный порт, из-за чего `Page.goto` падал по таймауту.
- Chrome-профили следует удалять, когда связанный процесс уже завершён; при параллельных сессиях нельзя завершать браузеры по шаблону имени профиля — только по PID, запущенным своей сессией.

## Как сделано
Автор оформил обнаруженные нюансы как постоянные инструкции для агента. В PowerShell 5.1 вместо операторов `&&` и `||` предлагает цепочку `A; if ($?) { B }`; для внешних программ не использовать `2>&1`, а проверять `$LASTEXITCODE`. Файлы лучше записывать встроенным инструментом Write, а при записи через PowerShell явно задавать `-Encoding utf8`.

Для поиска задач Python и завершения процессов нужно фильтровать `Win32_Process` по `CommandLine`, а затем проверять, что процесс действительно остановлен. Если команда отсутствует в окружении агента, следует сначала попробовать полный путь к исполняемому файлу; пример для Go: `& "C:\Program Files\Go\bin\go.exe" -C .\backend test ./...`.

Для Next.js 16 в режиме разработки автор рекомендует открывать страницу через `localhost`, а не `127.0.0.1`, если не работает HMR. Профили Chrome держать на SSD и удалять после прогона; удалять профиль только после завершения связанного Chrome, а завершать браузеры — лишь по PID, запущенным текущей сессией.

## Результаты
Автор превратил пять повторяющихся проблем в набор правил для памяти агента и готовый блок Windows для CLAUDE.md. После переноса профилей Chrome с HDD обратно на SSD и удаления их после каждого прогона проблема таймаутов исчезла в описанном сценарии; количественных сравнений до и после автор не приводит.

## Ограничения
Это личный практический опыт, а не систематическое тестирование. Причину, по которой классификатор в авторежиме пропускает `go test`, но блокирует `go vet`, автор не выяснил. Указанные симптомы зависят от конкретных версий и конфигурации: PowerShell 5.1, Next.js 16, Python из Microsoft Store и оборудования. Производительность HDD описана отдельными наблюдениями, без сравнительного бенчмарка.

## Что взять себе
- Сохраняйте в инструкциях агента особенности именно его оболочки и окружения: команды, доступные в пользовательском терминале, могут быть недоступны агенту.
- При сбоях автоматизации проверяйте не только код и сеть, но также имена процессов, адрес хоста и производительность диска.
- Останавливайте процессы адресно: находите их по командной строке, проверяйте завершение и не затрагивайте PID других сессий.
- Для повторяемых обходов удобно собрать краткие правила в CLAUDE.md, чтобы агент применял их в следующих задачах.
