## Коротко
Автор проверил, что вычисление эмбеддингов можно вынести в отдельный Python-сервис, не превращая отказ этой зависимости в сбой всего .NET API. При недоступности Python AI-запрос получил 503, а после восстановления контейнера снова завершился успешно без перезапуска API.

## Контекст
Автор описывает Enterprise GenAI Platform: основной сервер — модульный монолит на .NET 10 с маршрутами, прикладной логикой и PostgreSQL, а вычисления ИИ вынесены в отдельный Python AI Orchestrator. Задача — проверить границу между бизнес-логикой и ML-нагрузкой и предсказуемо обработать отказ вычислительного компонента.

## Главное
- Основной сервер — модульный монолит на .NET 10; отдельным процессом вынесен только специализированный AI Orchestrator на Python.
- Для сравнения используется sentence-transformers/all-MiniLM-L6-v2: локальная CPU-модель создаёт векторы размерности 384.
- Два текста кодируются одним вызовом encode([left, right]); затем вычисляется косинусное сходство.
- Внешний маршрут — POST /ai/semantic-similarity; внутренний маршрут Python — POST /semantic-similarity. Межсервисный транспорт — обычный HTTP.
- AiOrchestratorClient реализует IAiOrchestratorClient; типизированный HttpClient получает адрес Python и тайм-аут из конфигурации.
- Ошибки классифицируются как 503 при недоступном соединении, 504 при тайм-ауте и 502 при ошибочном ответе или нарушении контракта.
- X-Correlation-ID передаётся из .NET в Python и связывает журналы, но не заменяет OpenTelemetry.
- В Docker Compose используются PostgreSQL с pgvector, db-migrator, Python AI Orchestrator и Core API; модельный кэш хранится в томе huggingface_cache.
- При отказе Python Core API остался запущен; после пересоздания Python запрос повторили без перезапуска .NET.
- Указаны 21 тест .NET, 9 тестов Python и 2 фронтенд-теста; это не нагрузочные испытания.

## Как сделано
Для семантического сравнения используется sentence-transformers/all-MiniLM-L6-v2, работающая локально на CPU и выдающая эмбеддинги размерности 384. Python-сервис на FastAPI загружает модель при старте через lifespan и предоставляет POST /semantic-similarity; модель вызывается один раз для двух текстов, затем рассчитывается косинусное сходство. Входные данные дополнительно проверяются Pydantic.

Клиент обращается к POST /ai/semantic-similarity в .NET Core API, который вызывает Python по HTTP через AiOrchestratorClient и IAiOrchestratorClient. Адрес сервиса и тайм-аут задаются конфигурацией. Ошибки разделяются на недоступность соединения (503), тайм-аут (504) и ошибочный ответ или нарушение контракта (502); ProblemDetails не раскрывает внутренние сообщения. X-Correlation-ID проходит через оба сервиса и попадает в журналы.

Docker Compose запускает PostgreSQL с pgvector, одноразовый db-migrator, Python AI Orchestrator и Core API. Проверки готовности задают порядок запуска, а именованный том huggingface_cache сохраняет файлы модели. Отказ проверяли остановкой Python-контейнера, его пересозданием и повторным запросом без перезапуска .NET.

## Результаты
При остановленном Python Core API продолжил работать, а запрос семантического сравнения вернул 503. После пересоздания контейнера модель загрузилась, и тот же запрос без перезапуска .NET вернул HTTP 200 со score около 0,7598. Для пары близких описаний PostgreSQL получено 0,7598, для описания PostgreSQL и фразы о солнечной погоде — 0,0462. После пересоздания в кэше остались те же 48 файлов объёмом около 274 МБ. Автор сообщает о 21 тесте .NET, 9 тестах Python и 2 фронтенд-тестах.

## Ограничения
Это проверка сквозного пути и базового поведения при отказе, а не доказательство отказоустойчивости всей платформы или нагрузочный тест: не измерялись пределы параллельной обработки, длительная деградация и нехватка памяти. Во время отказа AI-функция недоступна; обработка ошибок не сохраняет её доступность. Не включены автоматические повторы и полноценная распределённая трассировка. all-MiniLM-L6-v2 ориентирована прежде всего на английский язык; качество для русскоязычных документов и пороги сходства не проверены. Косинусное сходство не является вероятностью истинности или гарантией эквивалентности утверждений, а сохранение кэша не фиксирует версию весов для строгой воспроизводимости.

## Что взять себе
- Выносить ML-компонент отдельно имеет смысл, когда его зависимости, ресурсы и жизненный цикл отличаются от основного API; не обязательно дробить на сервисы каждый прикладной модуль.
- Сетевую границу нужно сопровождать явным контрактом, тайм-аутами, классификацией ошибок и корреляционным идентификатором.
- Health check помогает при старте, но не защищает от последующего отказа зависимости — обработка ошибок в API всё равно необходима.
- Перед применением эмбеддингов в продукте проверьте модель и пороги на целевых языках и данных; score сам по себе не доказывает смысловую эквивалентность.
- Очереди, автоматические повторы и распределённую трассировку стоит добавлять, когда этого требуют длительность задач, измеренная нагрузка или эксплуатационные потребности.
