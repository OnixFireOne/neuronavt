## Коротко
Автор добавил в бота две проверки: эвристики ищут замаскированные установщики в README, а проверка пересказа сверяет имена и числа с исходником. На тестовой выборке первая выявила вредоносную приманку, вторая — три явные выдумки модели; обе проверки намеренно предпочитают пропустить сомнительный материал, а не показывать неподтверждённое.

## Контекст
Автор ведёт Telegram-бота, который каждое утро выбирает пять трендовых репозиториев GitHub с trendshift.io и по нажатию кнопки пересказывает README с помощью DeepSeek. После попадания в ленту поддельного репозитория «Microsoft Activation Scripts» автор решил проверить безопасность рекомендаций и достоверность кратких пересказов.

## Главное
- Поддельный репозиторий «Microsoft Activation Scripts» имел 1774 звезды; аккаунт владельца создали за 94 секунды до репозитория, а адрес установщика в README был записан задом наперёд.
- Ловушка использовала PowerShell-конструкцию вида `iex(irm(-join"…"[-1..-99]))`: адрес восстанавливался, скачанный скрипт сразу выполнялся.
- Простое правило «скачать и запустить с сайта вне GitHub» оказалось слишком широким: оно затронуло бы 38 из 314 нормальных проектов, включая codex и opencode.
- Признак молодого аккаунта сам по себе ненадёжен: на момент появления ловушки аккаунту было 34 дня; полезным оказалось сочетание возраста менее 30 дней на момент создания репозитория с малым размером или почти пустым содержимым.
- В эвристике README учитываются перевёрнутые строки, base64 с выполнением, скрытый запуск через mshta, certutil, bitsadmin или `-WindowStyle Hidden`; перед проверкой убираются невидимые символы и обратные кавычки PowerShell.
- Если репозиторий скрыт как подозрительный, бот подставляет следующий по рейтингу и объясняет причину; у исключённого проекта кнопки нет.
- Первая версия проверки основанности отклонила 9 из 303 пересказов; после нормализации написаний осталось 5 отказов, три из которых автор признал явными выдумками.
- Корректный пересказ про 百度 был отклонён из-за латинского «Baidu»; автор добавил таблицу китайских названий компаний.
- Скрипты называются `lure-check` и `ground-check`, написаны на Python с использованием стандартной библиотеки и имеют лицензию MIT.

## Как сделано
Для поиска приманок автор проверил два независимых признака. Первый ищет в README маскировку команды установки: вычисляемые или перевёрнутые адреса, base64 с немедленным выполнением, скрытый запуск и характерные PowerShell-конструкции. Перед анализом текст очищается от невидимых символов и обратных кавычек, которыми можно разбить команды. Второй признак сочетает молодость владельца — аккаунт создан менее чем за 30 дней до репозитория — с отсутствием содержимого: размер меньше 10 КБ либо только README и LICENSE. Если GitHub не отвечает, результат считается неизвестным, а не отсутствием кода. При срабатывании бот убирает репозиторий из подборки и подставляет следующий по рейтингу.

Для проверки пересказов инструмент извлекает из текста слова с заглавной латинской буквой и цифры длиной от трёх символов, а также числа с десятичной точкой или процентом, и требует, чтобы они присутствовали в источнике. Автор добавил нормализацию дефисов, пробелов и разделителей тысяч. Если пересказ не проходит проверку, бот показывает описание GitHub вместо него. Для китайских названий компаний добавлена таблица соответствий, поскольку написание 百度 в источнике не совпало с «Baidu» в пересказе.

Оба инструмента — отдельные однофайловые Python-скрипты, используют только стандартную библиотеку и распространяются под MIT. Запуск: `python3 lure_check.py owner/repo` (код возврата 1 для выявленной приманки) и `python3 ground_check.py --source source.txt --text summary.txt`.

## Результаты
На выборке из 314 живых репозиториев, присланных ботом с 15 июля по 8 октября, каждая из двух эвристик выявила ровно один случай — поддельный «Microsoft Activation Scripts». Широкое правило для любой установки «скачай и запусти» затронуло бы 38 из 314 нормальных проектов, поэтому автор его отверг. Проверка пересказов на 303 примерах сначала отклонила 9, затем после нормализации — 5: три содержали неподтверждённые названия Ruby, Cypress и Scratch, ещё два — NVIDIA и «XIX век» — источник не подтверждал. После рабочего сбоя с Baidu автор добавил таблицу китайских названий; за следующие четыре дня из 20 пересказов не было ни одного отказа. Фильтр приманок работает в боте с 9 октября.

## Ограничения
Фильтр угроз анализирует только README и метаданные: он не находит обычную ссылку на похожий домен без маскировки, архивные приманки на старых аккаунтах или вредоносный код внутри настоящего проекта. Архивные примеры автор не смог изучить, потому что GitHub удалил репозитории. Проверка пересказов основана на совпадении слов и чисел: она может пропустить ложное утверждение, если ключевое слово есть в источнике, а также выдумки строчными буквами и числа длиной в одну-две цифры. Возможны ложные отказы для корректных названий и сведений, которые источник не подтверждает; методика и результаты представлены автором на ограниченных выборках.

## Что взять себе
- Не блокируйте все команды «скачать и сразу выполнить»: такое правило может убрать полезные проекты; сочетайте несколько независимых признаков риска.
- Сверка имён и чисел с источником — недорогая проверка пересказов, но это фильтр на неподтверждённые детали, а не полноценная проверка фактической истинности.
- Для автоматических проверок различайте отсутствие данных и сбой доступа: ошибка сети не должна автоматически трактоваться как подозрительное содержимое.
- Если пересказ не проходит простую верификацию, безопасная альтернатива — показать исходное описание, а не пытаться угадать, корректна ли формулировка.
