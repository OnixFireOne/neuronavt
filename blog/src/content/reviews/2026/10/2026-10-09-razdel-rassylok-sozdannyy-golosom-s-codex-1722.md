## Коротко
Саймон Уиллисон описывает, как примерно за полчаса голосовой работой с Codex в ChatGPT Desktop создал для блога Django-архив рассылок. Голосом удалось сделать большую часть функции, но импорт из приватного GitHub-репозитория и финальная проверка потребовали ручной доработки и ещё около получаса текстовых запросов.

## Контекст
Автор — Саймон Уиллисон, разработчик и автор блога simonwillisonblog. Он хотел добавить отдельный тип записей для рассылок: еженедельные выпуски Substack и ежемесячные письма для спонсоров, с нужными правилами отображения, поиска и импорта в существующий Django-сайт.

## Главное
- Автор работал в ChatGPT Desktop, во вкладке Codex, подключив агента к локальной среде разработки Django.
- В качестве модели указана GPT-6 Astra High; голосовая сессия заняла около получаса — примерно столько длилось приготовление ужина.
- Новая модель Django и миграция отделили рассылки от других типов контента; записи не должны появляться на главной и страницах тегов, но должны присутствовать в архивах по датам.
- Созданы четыре импорта: последние выпуски Substack через RSS, остальные — через недокументированный API Substack, публичный архив из simonw/monthly-newsletter-archive и последнее закрытое письмо из приватного репозитория.
- Появились /newsletters/ и /newsletters/2026/; выпуски сортируются по дате, а ниже размещены ссылки на архивы по годам.
- Еженедельные рассылки Substack ссылаются на исходные страницы, а опубликованные ежемесячные письма получили собственные страницы на сайте и попали во внутренний поиск.
- Первоначально один импорт использовал Git как subprocess. Автор заменил его API-импортом, поскольку данные находились в приватном репозитории.
- Код проверяли через pull request на GitHub; после голосовой работы автор потратил ещё около получаса на текстовые запросы и правки.
- Для автора ключевое преимущество такого режима — возможность заниматься разработкой параллельно с другим делом; при точной настройке он предпочитает клавиатуру.

## Как сделано
Работа велась в приложении ChatGPT Desktop, во вкладке Codex, в локальной копии сайта. Автор начал с команды «Start dev server and open in browser», чтобы получить предпросмотр, а затем включил голосовой чат и обсуждал требования, пока готовил ужин. Использовалась модель GPT-6 Astra High; она задавала уточняющие вопросы и меняла код.

Codex подготовил Django-модель и миграцию, настройки Django Admin, представления и шаблоны, а также импорты: последние выпуски Substack через RSS, остальные — через недокументированный API Substack, опубликованные ежемесячные письма из публичного репозитория GitHub и последнее закрытое письмо из приватного репозитория. После этого автор попросил создать ветку и pull request. При проверке он заменил импорт через Git в subprocess на импорт через API и внёс правки в отображение страниц; эту часть делал текстовыми запросами.

## Результаты
В блоге появились страницы /newsletters/ и /newsletters/2026/, годовые архивы и отдельные страницы для архивных ежемесячных выпусков. Рассылки показываются на страницах архивов по дням и месяцам, но не на главной и не в тегах. Еженедельные выпуски ведут на Substack, а ежемесячные доступны на сайте; они также включены в поиск. После проверки pull request изменения были готовы к развёртыванию. Численных оценок качества или производительности автор не приводит.

## Ограничения
Это описание одного проекта, а не систематическая оценка голосового программирования. Автор не сообщает о независимой проверке результата, стоимости использования или сравнении скорости с полностью текстовой работой. Голос оказался неудобен для передачи кода, примеров и сообщений об ошибках; приватный репозиторий потребовал ручного решения по API-импорту. В статье говорится о готовности к развёртыванию, но не приводятся отдельные данные о работе функции после релиза.

## Что взять себе
- Голосовой интерфейс с локальным предпросмотром подходит для обсуждения требований и черновой реализации, особенно когда можно работать параллельно с бытовыми делами.
- До начала работы стоит чётко определить правила показа и поиска нового типа контента: это помогает агенту учесть связи с существующими архивами сайта.
- Для финальной доработки кода клавиатура остаётся эффективнее: проще передать примеры, ошибки и конкретные фрагменты, которые нужно изменить.
- Даже при успешной генерации кода важны обычная проверка pull request и ручная адаптация импорта к ограничениям доступа, например к приватным репозиториям.
