## Коротко
Автор доработал Go-лаунчер llama-runner, чтобы он запускал локальный llama-server, ждал его готовности и затем открывал Claude Code с нужной конфигурацией. В статье разобраны три практические проблемы связки — имена моделей, конфликт серверных логов с TUI и ошибка Jinja-шаблона Qwen — и показано, как их обойти.

## Контекст
Автор развивает llama-runner для запуска GGUF-моделей через llama.cpp на ограниченном оборудовании. Прежняя версия упрощала запуск llama-server; новая добавляет автоматический запуск Claude Code, чтобы не управлять сервером и клиентом в отдельных терминалах.

## Главное
- Новая версия llama-runner по умолчанию запускает llama-server, ожидает /health и затем открывает Claude Code; `-server` оставляет только серверный режим.
- Поскольку Claude Code ожидает имена вроде claude-sonnet-4 и claude-haiku-4, флаг `-alias` задаёт общее имя через `--alias` и переменные ANTHROPIC_DEFAULT_SONNET_MODEL, ANTHROPIC_DEFAULT_HAIKU_MODEL и ANTHROPIC_DEFAULT_OPUS_MODEL.
- Если `-alias` явно не задан и не включён `-server`, лаунчер автоматически использует `local`; явную передачу флага определяют через `flag.Visit`.
- Вывод llama-server в режиме с Claude Code направляется в `~/.cache/llama-runner/llama-server.log`, чтобы не нарушать перерисовку TUI. Для этого предусмотрены `-log-file` и `-quiet-server`; в режиме `-server` логи идут в терминал.
- Ошибка 500 `System message must be at the beginning` связана, по объяснению автора, со стандартным Jinja-шаблоном Qwen 3.8 и порядком системного сообщения при повторном запросе Claude Code.
- В качестве исправления предлагается шаблон `froggeric/Qwen-Fixed-Chat-Templates` с Hugging Face; его путь по умолчанию — `~/GGUF/qwen-fixed-chat-template.jinja`, а загрузка выполняется через `curl -fL`.
- Флаг `-chat-template` позволяет указать другой шаблон; `-chat-template ""` отключает пользовательский шаблон. Если файла нет, лаунчер предупреждает и запускает сервер без `--chat-template-file`.
- После выхода из Claude Code лаунчер посылает серверу SIGINT и ждёт завершения, чтобы процесс не оставался работать в фоне.
- Дополнительные параметры охватывают контекст `-c`, размеры батча `-b` и `-ub`, flash attention `-fa`, параллельные слоты `--parallel`, инструменты `-tools`, Jinja `-jinja`, mmap `-lm-lazy` и MCP-прокси `-webui-mcp-proxy`.
- MCP-прокси запускает `mcp-search-server` на порту :8090; автор советует не оставлять `--tools all`, если сервер доступен не только через 127.0.0.1.

## Как сделано
В обычном режиме llama-runner запускает llama-server, ожидает доступности эндпоинта /health с настраиваемым таймаутом и стартует claude с переменными ANTHROPIC_BASE_URL, ANTHROPIC_AUTH_TOKEN, ANTHROPIC_API_KEY и ANTHROPIC_DEFAULT_*_MODEL. Флаг -alias передаётся серверу как --alias и задаёт имена Sonnet, Haiku и Opus для клиента. Если -alias не указан, а -server не активен, используется local; автор проверяет явную передачу флага через flag.Visit.

Чтобы логи не портили полноэкранный интерфейс Claude Code, stdout и stderr llama-server в совместном режиме перенаправляются в ~/.cache/llama-runner/llama-server.log. Это настраивается флагами -log-file и -quiet-server; в режиме -server логи остаются в терминале. При завершении Claude Code лаунчер посылает серверу SIGINT и ждёт его остановки.

Для обхода ошибки Qwen «System message must be at the beginning» автор предлагает скачать исправленный Jinja-шаблон командой `curl -fL -o ~/GGUF/qwen-fixed-chat-template.jinja https://huggingface.co/froggeric/Qwen-Fixed-Chat-Templates/resolve/main/chat_template.jinja`. Флаг -chat-template по умолчанию указывает на этот файл и передаёт серверу --chat-template-file. Файл следует проверить через `head -20` и `grep -n "System message must be at the beginning"`; пустое значение `-chat-template ""` отключает пользовательский шаблон. Если файл не найден, лаунчер предупреждает и продолжает запуск без него.

## Результаты
Получился лаунчер с двумя основными режимами: по умолчанию он запускает сервер и Claude Code, а с -server — только сервер, сохраняя прежнее поведение. Автор сообщает, что связка с локальными моделями позволяет получить агентную среду без облака и ежемесячной платы, но численных тестов производительности или сравнения качества в этой статье не приводит. Код открыт на GitHub; сборка выполняется через `go build -o llama-runner .`.

## Ограничения
Инструкция ориентирована на Linux и модели GGUF; универсальная совместимость разных моделей и шаблонов не подтверждена. Исправленный шаблон приведён как внешний файл, который нужно самостоятельно загрузить и проверить. В статье нет измерений скорости, качества, стоимости оборудования или систематических тестов. Автор отдельно предупреждает, что `--tools all` рискован при открытии порта не только на 127.0.0.1; следует ограничить инструменты через -tools.

## Что взять себе
- Локальный OpenAI-совместимый сервер можно подключить к Claude Code, если согласовать имя модели через alias и передать клиенту адрес и переменные окружения.
- Полноэкранные терминальные клиенты требуют отделять серверные логи от stdout/stderr клиента; перенаправление в файл предотвращает порчу TUI.
- Ошибки форматирования запросов могут быть вызваны шаблоном чата, а не самой моделью или лаунчером; проверяйте используемый Jinja-шаблон и его содержимое.
- Автоматизация запуска и корректного завершения сервера упрощает повседневную работу, но доступные инструменты нужно ограничивать при сетевой экспозиции.
