## Коротко
Автор обнаружил, что Claude Code регулярно отправляет транскрипты фоновых агентов модели для короткой сводки, и предлагает Linux-хук, который отключает эти запросы, уменьшая расход лимита; это полезно пользователям с фоновыми агентами.

## Контекст
Автор Flamerix AI заметил в OpenTelemetry Claude Code, что запросы со значением query_source = agent_summary могли расходовать больше, чем основной диалог. По статье, сводки включены по умолчанию с версии 2.1.232.

## Главное
- Каждые примерно 30 секунд Claude Code, согласно статье, отправляет модели полный транскрипт каждого фонового агента и просит описать последнее действие в 3–5 словах; результат нужен только для строки статуса.
- По телеметрии автора, до отключения сводочные запросы занимали 19,7% всех запросов и 16,4% расходов, хотя не попадали в обычные журналы сессий.
- В настройках нет обычного переключателя, который выключал бы таймер; предлагаемый обходной путь перехватывает таймер через Bun preload.
- Агенты и фоновые задачи продолжают работать, но статус агента больше не обновляется сводкой. После обновлений нужно заново проверять, что хук срабатывает.

## Как сделано
Предложен Bun preload-хук no-agent-summary.js. Он оборачивает setTimeout и setInterval и распознаёт таймер сводки по текстовому якорю в исходнике callback; такой таймер заменяется не срабатывающим, остальные таймеры пропускаются. Установка начинается с загрузки скрипта в ~/.local/share/no-agent-summary.js, затем Claude Code запускается с BUN_OPTIONS="--preload /абсолютный/путь/no-agent-summary.js". Для постоянного действия переменную задают в окружении или обёртке запуска. Нужно перезапустить daemon и уже работающие сессии командой claude daemon stop --any. CC_AGENT_SUMMARY_MODE=pass служит контрольным режимом: хук загружается, но таймеры не отключаются. Проверку автор рекомендует повторять после каждого обновления.

## Результаты
В телеметрии автора доля расходов на agent_summary снизилась с 16,4% до 0%, а доля API-запросов — с 19,7% до 0% через два дня после установки. В одном измерении запуск claude --version занял около 17 мс вместо 10 мс. Автор сообщает, что в версиях 2.1.257–2.1.312 тестовые запуски с хуком в режиме off дали ноль сводочных запросов.

## Ограничения
Проверено на Linux; macOS и Windows не проверены. Хук зависит от совпадения текста внутри callback, поэтому обновление Claude Code может незаметно сделать его неработающим. Отключается только сводка и обновление статуса агента: строка статуса перестаёт обновляться, а SDK task_progress не получает сводку. Оценка расходов в статье — внутренняя оценка Claude Code, не счёт; подписчикам это скорее расходует запас лимита. Изменение поведения клиента может противоречить условиям сервиса. Автор предупреждает об использовании на свой риск.

## Что взять себе
- Проверьте собственную телеметрию OpenTelemetry: авторские проценты не гарантируют таких же расходов у вас.
- Если решите использовать хук, задайте BUN_OPTIONS с абсолютным путём и перезапустите daemon и текущие сессии.
- После каждого обновления Claude Code проверьте логи или query_source = agent_summary; при сбое запросы могут вернуться незаметно.
- Учитывайте, что изменение касается только сводок статуса, а не работы фоновых агентов в целом.
