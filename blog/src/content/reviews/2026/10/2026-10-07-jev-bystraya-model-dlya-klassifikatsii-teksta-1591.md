## Коротко
Jev от TypeSafe не генерирует свободный текст, а отвечает на заранее заданные вопросы типизированными значениями и вероятностями. Она может ускорить маршрутизацию тикетов и похожие задачи, но заявленные характеристики и качество вероятностей нужно проверять на собственных данных, особенно для русского языка.

## Контекст
Автор заметки Нженга тестирует Jev — модель компании TypeSafe, основанной Диогу Алмейдой, бывшим исследователем OpenAI, работавшим над ChatGPT и RLHF. Статья рассматривает альтернативу вызовам чат-моделей для простых решений вроде выбора категории обращения: свободный текст приходится разбирать, а сам вызов может быть медленным и дорогим.

## Главное
- Jev отвечает не свободным текстом, а структурированными результатами по заранее заданным вопросам.
- Choice выбирает из заданных вариантов, Score оценивает по описанной шкале, Noul возвращает вероятность истинности утверждения.
- В одном запросе можно смешать несколько типов вопросов; модель обрабатывает их параллельно.
- На тестовом тикете о Stripe получены техническая категория с уверенностью 72%, срочность 99% и раздражение 1 из 2 за 72 мс.
- В повторных примерах документации два результата совпали, но оценка для «Вы бот?» составила 0.26 вместо опубликованных 0.40.
- TypeSafe заявляет 70–500 мс, $0.042 за миллион входных токенов и бесплатные выходные токены; сравнительные преимущества — до 193 раз по скорости и до 444 раз по цене.
- Автор отмечает, что бенчмарки подготовила команда TypeSafe, а цена и сравнительные заявления независимо не подтверждены.
- По описанию, запрос ограничен 64k токенами; состояние вместе с самым длинным вопросом — 32k. Точность может снижаться на длинных состояниях.
- Основной язык обучения — английский; публичных результатов тестирования на русском в статье не найдено.
- В статье сообщается о смене лимитов API и доступе по листу ожидания.

## Как сделано
Jev принимает текстовое состояние или JSON и набор заранее описанных вопросов. Для каждого возвращает ответ заданного типа: Choice выбирает вариант из списка, Score выставляет оценку по заданной шкале, Noul оценивает вероятность истинности утверждения. Типы можно смешивать в одном запросе; вопросы обрабатываются параллельно для одного состояния.

Автор проверил модель на тикете о проблеме с подключением Stripe и повторил три примера из документации TypeSafe. В продуктовой логике предполагается использовать вероятностные пороги: автоматизировать действия при высокой уверенности, уточнять при средней и передавать человеку при низкой. Такие пороги следует настраивать по размеченным примерам своей команды.

## Результаты
На тикете о подключении Stripe модель ответила за 72 мс: отнесла обращение к техническому отделу с уверенностью 72%, оценила срочность в 99%, а раздражение клиента — в 1 по шкале до 2. В двух повторённых примерах из документации значения совпали: «Спасибо, помогло!» получило 0.02, просьба поговорить с человеком — 0.99. Для фразы «Вы бот?» автор получил 0.26 вместо опубликованных TypeSafe 0.40. Это демонстрационные проверки, а не оценка качества на репрезентативной выборке.

## Ограничения
TypeSafe заявляет задержку 70–500 мс, цену $0.042 за миллион входных токенов и бесплатные выходные токены, а также преимущество до 193 раз по скорости и до 444 раз по цене относительно фронтирных LLM. По статье, бенчмарки создавались командой TypeSafe, а независимое подтверждение несубсидированной цены отсутствует; серверы находятся на западном побережье США, поэтому задержка зависит от региона. Одно расхождение с примером из документации не позволяет судить о калибровке; автор предполагает возможное влияние версии модели 1.13, но проверить это не смог. Модель не предназначена для многошаговых рассуждений, работает только с текстом, обучалась преимущественно на английском, а качество на других языках, включая русский, требует проверки. Указаны ограничения контекста: 64k токенов на запрос, но состояние вместе с самым длинным вопросом — не более 32k; точность падает при росте состояния. Лимиты API менялись: в заметке указаны 250 тыс. токенов в секунду и 1200 запросов в минуту, тогда как документация на 7 октября — 100 тыс. токенов и 80 запросов в секунду. Доступ предоставлялся по листу ожидания.

## Что взять себе
- Для классификации, маршрутизации и простых проверок Jev может заменить хрупкие регулярные выражения или дорогой вызов чат-модели.
- Не принимайте вероятности за готовую калибровку: настройте пороги на размеченных данных и отдельно проверьте ошибки и передачу сложных случаев человеку.
- Для русскоязычной поддержки сначала прогоните реальные размеченные обращения; единичный быстрый ответ не подтверждает качество.
- Перед внедрением перепроверьте актуальные лимиты, доступность, задержку из своего региона и стоимость на реальной нагрузке.
