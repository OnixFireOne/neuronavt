## Коротко
Интеграция подключает к Codex инструменты Wordstat, чтобы маркетолог мог получать частотности запросов прямо в чате и сверять выводы ИИ с данными сервиса.

## Контекст
Автор описывает задачу: модель предлагала поисковые формулировки без проверки спроса, поэтому данные приходилось вручную сверять в Wordstat. Для статьи подготовлен Python-пакет wordstat-v0.1.1; код и тесты опубликованы в открытом репозитории.

## Главное
- Интеграция возвращает исходные фразы и частотности Wordstat в том же диалоге, где агент их анализирует.
- Четыре узких инструмента безопаснее и проще для модели, чем универсальный доступ к HTTP; все операции только читают данные.
- Общий сервисный слой делает поведение CLI и MCP одинаковым, а кэш помогает не повторять одинаковые платные запросы.
- В первой демонстрации модель ошиблась в значении устройства, и клиент отклонил запрос до обращения к Wordstat; позже MCP прочитал сохранённый результат.
- Получение фраз и частотностей — лишь проверка спроса: для выбора ключей кампании нужны данные о продукте, посадочной странице и целях рекламы.

## Как сделано
Пакет предоставляет четыре инструмента только для чтения: популярные запросы, динамику, распределение по регионам и дерево регионов. CLI, MCP-сервер и Python-код используют общий сервисный слой с валидацией, файловым кэшем и обработкой ошибок. Секреты задаются в .env, а в конфигурации Codex перечисляются разрешённые инструменты. Повторные запросы обслуживаются кэшем: обычные ответы хранятся семь дней, дерево регионов — 30 дней; refresh=true обходит кэш. Для временных ошибок предусмотрены повторы с экспоненциальной задержкой.

## Результаты
Успешный проход с вызовами трёх платных методов стоит 0,09 ₽ по тарифам, проверенным 23 октября 2026 года; расходы на ИИ-модель не включены. В опубликованном теге прошли 12 модульных тестов: 12 passed in 2.03s. В демонстрации MCP вернул сохранённый снимок от 20 октября; доступность API на 23 октября этим не проверялась.

## Ограничения
Это первая версия: она не формирует единый исследовательский отчёт и не кластеризует фразы. MCP ограничивает топ 200 фразами, а список устройств принимает как строки и проверяет внутри клиента. Интеграционные тесты с живым API не запускаются в публичном CI; файловый кэш рассчитан на одного пользователя и не координирует процессы на разных машинах. Агент с доступом к файлам проекта может получить доступ к локальным секретам; отдельного лимита расходов нет.

## Что взять себе
- Проверяйте частотность и формулировки по ответу инструмента, а не только по объяснению модели.
- Перед запросом смотрите параметры вызова, особенно регион, устройства и лимит.
- Для больших выгрузок используйте CLI, а в чат передавайте только нужную часть данных.
- Учитывайте кэш: успешное чтение сохранённого ответа не доказывает, что API доступен сейчас.
