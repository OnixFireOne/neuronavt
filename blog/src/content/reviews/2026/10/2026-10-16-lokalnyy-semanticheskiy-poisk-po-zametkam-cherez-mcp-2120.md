## Коротко
Автор собрал локальный MCP-сервер, который находит заметки по смыслу и подключается к Claude Code без платных API и передачи данных наружу. Статья подробно разбирает нарезку текста с учётом лимита модели, обновляемый кэш и меры для надёжной и безопасной работы сервера.

## Контекст
Автор — разработчик собственного проекта для поиска по личным заметкам о встречах; конкретная компания и должность не указаны. Проблема: обычный поиск не находит заметки, если в запросе употреблены другие слова, а отправлять их во внешний сервис ради эмбеддингов автор не хотел.

## Главное
- Сервер предоставляет `search_notes(query, limit=5)`, `list_notes()` и `read_note(filename)`; все инструменты только читают.
- Модель `paraphrase-multilingual-MiniLM-L12-v2` поддерживает более 50 языков, выдаёт векторы длиной 384 и занимает около 120 МБ; для первого запуска требуется загрузка, затем сеть не нужна.
- Лимит MiniLM — 128 токенов. С запасом `TOKEN_MARGIN = 4` фрагменты ограничиваются 124 токенами, чтобы модель не отбрасывала хвосты незаметно.
- Параметры нарезки: `CHAR_TARGET = 500`, `CHAR_MAX = 600`, `CHAR_OVERLAP = 80`; длинные строки сначала делятся по предложениям, а затем — по токенам.
- Кэш `.index/cache.pkl` учитывает относительные пути, `mtime`, модель, версию формата кэша и параметры чанкинга; запись выполняется через временный файл и замену.
- Семантическая близость считается скалярным произведением нормализованных эмбеддингов. Для запросов максимум из двух слов или при максимуме ниже `KEYWORD_SIM_THRESHOLD = 0.35` включается словесный фоллбэк с `KEYWORD_WEIGHT = 0.15`.
- Точному совпадению слова присваивается 1.0, совпадению подстрокой — 0.5; подстрочный поиск разрешён для слов длиной от четырёх букв. Числа в запросах сохраняются.
- В зависимостях зафиксированы `mcp==1.27.2`, `sentence-transformers==5.5.1`, `numpy==2.4.6`; требуется Python `>=3.11`. Более крупная `paraphrase-multilingual-mpnet-base-v2` упомянута как потенциально точная, но примерно гигабайтная и более медленная.
- Для MCP через stdio нельзя писать служебный вывод в stdout: прогресс отключён, логи направляются в stderr, предупреждения токенизатора приглушаются.
- При чтении файла сервер раскрывает путь через `resolve()`, проверяет, что он находится внутри корня заметок, и разрешает только `.md` и `.txt`. Команда регистрации: `claude mcp add notes -- uv run --directory <папка проекта> python server.py`.

## Как сделано
Решение состоит из `search_index.py` с движком индексации и `server.py` с тремя MCP-инструментами: `search_notes`, `list_notes` и `read_note`. Используются Python >=3.11, `mcp==1.27.2`, `sentence-transformers==5.5.1`, `numpy==2.4.6` и модель `paraphrase-multilingual-MiniLM-L12-v2` (384-мерные векторы). Модель загружается при первом обращении; после загрузки поиск работает локально и без интернета.

Текст заметок `.md` и `.txt` разбивается на фрагменты по строкам и предложениям, затем проверяется токенизатором модели. При лимите модели 128 токенов автор оставляет 4 токена под служебные метки, то есть ограничивает фрагмент 124 токенами; также заданы `CHAR_TARGET = 500`, `CHAR_MAX = 600` и `CHAR_OVERLAP = 80`. Эмбеддинги нормализуются, а близость вычисляется матричным умножением. Для запросов до двух слов или при максимальной близости ниже `0.35` добавляется поиск точных слов: вес совпадений — `0.15`.

Векторы и фрагменты кэшируются в `.index/cache.pkl`. Записи сверяются по относительному пути и времени изменения; версия модели и параметры разбиения входят в метаданные кэша, а несовпадение параметров приводит к перестроению. Для MCP автор отключает прогресс-бар и направляет логи в stderr, чтобы stdout оставался чистым каналом протокола. `read_note` нормализует путь через `resolve()` и не позволяет выйти за корень заметок; читаются только `.md` и `.txt`. Подключение к Claude Code: `claude mcp add notes -- uv run --directory <папка проекта> python server.py`; после регистрации нужна новая сессия.

## Результаты
На трёх тестовых заметках сформировалось 12 фрагментов: 323–492 символа и 88–123 токена. Добавление четвёртой заметки вызвало пересчёт только одного файла; повторный запуск без изменений не пересчитывал ни одного. В живом тесте Claude Code запрос о найме вывел на первое место заметку о собеседовании с близостью `0,5735`. Автор также проверил поиск по тематическим словам, имени компании и числу `200`, а самотест сервера проверяет попытку выхода за пределы папки и запрос отсутствующего файла.

## Ограничения
Оценка проведена лишь на четырёх тестовых заметках; пороги `0.35` и `0.15` не проверены на большой коллекции. Время изменения файла может не заметить содержимое, заменённое с сохранением mtime. Кэш использует `pickle`: загружать чужой или подменённый `cache.pkl` опасно, поскольку он может выполнить код. Поиск ключевых слов перебирает фрагменты на Python и не рассчитан на сотни тысяч записей. MiniLM уступает более крупным моделям в тонких смысловых различиях, а нарезка ослабляет связь между удалёнными частями текста. Поддерживаются только UTF-8 `.md` и `.txt`; нет удалённого доступа и веб-интерфейса. Скорость нарезки автор не измерял; установка PyTorch занимает ещё примерно 1–2 ГБ диска, а точность не сравнивалась количественно с альтернативами.

## Что взять себе
- Для локального семантического поиска полезно проверять длину чанков именно токенизатором выбранной модели: лимит по символам не гарантирует, что текст целиком попадёт в эмбеддинг.
- Кэш с инвалидацией по mtime экономит повторные вычисления, но для надёжности можно использовать хэш содержимого; не загружайте недоверенные файлы `pickle`.
- Семантический поиск стоит дополнять точным поиском слов, особенно для коротких запросов, имён и чисел; пороги нужно калибровать на собственной коллекции.
- MCP-серверу на stdio нужны чистый stdout и проверка путей, если имя файла приходит через инструмент, управляемый моделью.
